# 포켓몬 GO 슈퍼리그 계산기

정적 웹 도구 두 개.

| 페이지 | 하는 일 |
| --- | --- |
| `index.html` | **CCT** — 차징기를 몇 번째 일반기술 직후에 눌러야 하는지 |
| `cmp.html` | **CMP** — 같은 턴에 차징기를 쓰면 누가 먼저 나가는지 |
| `ivs.html` | **개체값** — 슈퍼리그에서 공격이 낮은 개체가 좋은 이유 (초보자용) |
| `team.html` | **팀 조합** — ABB · ABA · ABC · XAB 구조 (초보자용) |
| `types.html` | **타입 상성** — 18×18 상성표와 포켓몬별 약점 (초보자용) |

## 여는 법

`index.html` 을 브라우저로 열면 끝이다. 빌드도 서버도 필요 없다.

데이터를 `fetch()` 가 아니라 `<script src="data/data.js">` 로 읽는 이유가 여기 있다 —
`file://` 로 열면 `fetch()` 는 CORS에 막힌다. 데이터 형식을 바꿀 일이 있어도 이 제약은 지킬 것.

## 데이터 갱신

```bash
# 1. 수집기를 먼저 돌린다 (각 폴더에서)
python ../pogo-image-fetcher/scripts/fetch_assets.py
python ../pogo-move-fetcher/scripts/fetch_moves.py

# 2. 둘을 합쳐 이 도구의 데이터로 만든다
python scripts/build_data.py
```

`build_data.py` 는 두 수집기의 결과를 `speciesId` ↔ `id` 로 조인해 `data/data.js` 를 만들고
스프라이트를 `images/` 로 복사한다. 폴더가 자체 완결이라 통째로 옮기거나 공유해도 동작한다.

## CCT 계산식

내 일반기술을 **k회** 쓴 직후에 차징을 누른다. 그때까지 흐른 턴은 `k × m` (m = 내 기술 턴).
상대 기술이 끝나기 **직전**에 눌러야 공짜 턴을 안 준다:

```
k × m  ≡  o − 1   (mod o)        o = 상대 기술 턴
```

`gcd(m, o)` 가 `o − 1` 을 나누지 못하면 해가 없다. 그때는 도달 가능한 가장 큰 나머지를 쓰고
모자란 만큼이 손해 턴이 된다 (예: 내 2턴 vs 상대 4턴 → 1턴 손해).

특수한 경우 두 가지:

- **상대가 1턴 기술** — 매 턴 끝나므로 언제 눌러도 같다. 에너지·CMP를 우선
- **서로 같은 턴** — 나머지가 늘 0이라 정렬이 불가능하다

이 식은 참고 치트시트의 5×5 = **25칸 전부와 대조해 검증**했다. 계산부를 고치면 그 25칸으로
회귀 확인할 것 (`app.js` 의 `cct()` / `cellText()`).

## CMP 계산식

```
공격 실수치 = (종족값 공격 + 공격 개체값) × CPM(레벨)
CP         = ⌊공격 × √방어 × √HP ÷ 10⌋
```

같은 턴에 양쪽이 차징기를 쓰면 **공격 실수치가 높은 쪽이 먼저** 나간다.
PvPoke 시뮬레이터도 `poke.stats.atk > opponent.stats.atk` 로만 판정한다.

- **그림자는 CMP에 영향이 없다.** 그림자 보정(×1.2)은 데미지 계산에서만 곱해진다
- **동점이면 어느 쪽도 우선권이 없다** (사실상 랜덤)
- **레벨이 개체값에 따라 같이 움직인다.** CP 1500 상한 때문에 공격 개체값이 낮으면
  레벨을 더 올릴 수 있어서, 공격 개체값이 높다고 CMP에 유리한 게 아니다

레지스틸이 그 예다. 공격 개체값 15는 CP 상한에 걸려 Lv22.5(공격 100.12)에서 멈추지만,
공격 개체값 14는 Lv23까지 올라가 **공격 100.58** 로 더 높다.

프리셋 세 가지는 4,096조합을 전수 탐색해 구한다 — 1등 개체(스탯곱 최대),
공격 최대, 15·15·15. 1등 개체는 스탯곱을 위해 공격 개체값을 0으로 깎으므로 CMP에 불리하다.

## 구조

```
index.html        CCT 페이지        app.js
cmp.html          CMP 페이지        cmp.js
ivs.html          개체값 가이드      ivs.js
team.html         팀 조합 유형       team.js
types.html        타입 상성         types.js
                  (모두 좌측 사이드바 + 본문 구조를 공유한다)
style.css         전 페이지 공용
common.js         데이터·검색·포켓몬 선택 콤보박스 (공용)
data/data.js      window.POKEMON (1,152종, 종족값 포함) + window.CPM + window.TYPES
images/*.webp     스프라이트 1,152장
scripts/build_data.py
```

`common.js` 와 `app.js`/`cmp.js` 는 전역 스코프를 공유하는 일반 스크립트다.
같은 이름을 두 파일에서 선언하면 `SyntaxError` 로 **스크립트 전체가 죽는다**.
file:// 에서는 그 에러가 `Script error.` 로만 보여서 원인을 찾기 어렵다 — 이름을 겹치지 말 것.

## 타입 상성

`TYPES.chart[공격타입][방어타입]` = 배율. 포켓몬 GO는 본편과 배수가 다르다.

| 구분 | 배율 |
| --- | --- |
| 효과가 굉장하다 | ×1.6 |
| 효과가 별로다 | ×0.625 |
| 이중 저항 | ×0.390625 |

**포켓몬 GO에는 완전 무효가 없다.** 본편에서 ×0 인 조합도 ×0.390625로 조금은 들어간다.
두 타입이면 배율이 곱해져서 ×2.56(이중 약점)이나 ×0.39(이중 저항)가 나온다.

표는 PvPoke `DamageCalculator.js` 의 타입별 약점·저항·무효 목록에서 뽑는다. 타입을
이름으로 적어 둬서 순서를 추측할 필요가 없기 때문이다. 공식 GAME_MASTER 의 `attackScalar`
배열과 **324칸 전부 대조해 일치**를 확인했다.
